# 1. Pendahuluan

Sistem autentikasi merupakan salah satu komponen paling kritis dan sering diakses dalam berbagai aplikasi modern. Dalam lingkungan berskala besar dengan tingkat konkurensi yang tinggi (*high-concurrency*), kinerja sistem autentikasi sangat bergantung pada kemampuan mesin untuk mengelola ribuan permintaan (*requests*) secara simultan. Salah satu platform yang sering digunakan untuk mengembangkan aplikasi *backend* berkinerja tinggi adalah Node.js, yang memiliki keunggulan arsitektur *non-blocking I/O* dan model *single-threaded event-loop*.

Namun, di samping *framework* yang digunakan, pemilihan arsitektur penyimpanan data (basis data) juga dipercaya menjadi faktor penentu dalam kinerja aplikasi, terutama dalam hal kecepatan *baca-tulis* data pengguna. Terdapat dua paradigma basis data dominan: SQL (*Structured Query Language*) seperti PostgreSQL, dan NoSQL (*Not Only SQL*) seperti MongoDB. Masing-masing sistem basis data memiliki keunggulan teoretis; PostgreSQL menonjol pada integritas relasional dan kepatuhan ACID, sementara MongoDB sering dinilai lebih fleksibel dan memiliki latensi I/O yang cepat untuk operasi berbasis dokumen.

Meskipun banyak studi membandingkan kapabilitas *query* SQL versus NoSQL secara umum, terdapat gap pemahaman mengenai perilaku keduanya saat berinteraksi dengan beban komputasi berat di lapisan aplikasi (*application layer*), seperti enkripsi kata sandi. Mayoritas aplikasi memanfaatkan algoritma *hashing* kriptografis standar seperti Bcrypt untuk mengamankan kata sandi. Bcrypt merupakan algoritma yang secara inheren didesain *CPU-bound* (membutuhkan komputasi CPU intensif) demi mencegah serangan *brute-force*.

Masalah timbul ketika ribuan permintaan *login* masuk bersamaan ke peladen Node.js. Ketidaktahuan mengenai dampak algoritma kriptografi *CPU-bound* terhadap tumpukan antrean koneksi basis data di tengah beban puncak sering kali mengakibatkan kesalahan diagnosis masalah (salah menilai bahwa basis datanya yang lambat). 

Oleh karena itu, penelitian ini bertujuan untuk melakukan analisis komparatif performa antara PostgreSQL dan MongoDB pada sebuah sistem autentikasi Node.js (menggunakan Bcrypt) dalam kondisi *high-concurrency*. Fokus metrik utama adalah *Throughput* (*Requests per Second* / RPS) dan *Latency*. Penelitian ini tidak hanya bertujuan mencari basis data mana yang lebih baik untuk skenario tersebut, tetapi juga berkontribusi untuk mengidentifikasi dan membedah letak kegagalan (*bottleneck*) sesungguhnya—guna memberikan landasan arsitektural yang lebih baik untuk para pengembang aplikasi di masa depan.
