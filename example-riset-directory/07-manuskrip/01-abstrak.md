# Abstrak

**Abstrak**—Penelitian ini menguji dan membandingkan performa PostgreSQL (SQL) dan MongoDB (NoSQL) pada sistem autentikasi berbasis Node.js di bawah kondisi beban tinggi (*high-concurrency*). Pengujian dilakukan menggunakan perkakas Autocannon dengan 500 koneksi bersamaan selama 30 detik, serta menggunakan algoritma *hashing* Bcrypt (10 *salt rounds*). Hasil eksperimen menunjukkan bahwa PostgreSQL unggul secara signifikan dengan rata-rata *throughput* sebesar 14.67 *Requests per Second* (RPS), sementara MongoDB hanya mencapai 0.31 RPS dengan tingkat kegagalan (*timeout*) yang tinggi sebanyak 1.992 *requests*. Analisis kegagalan (*failure analysis*) menemukan bahwa anomali performa dan *bottleneck* tersebut tidak bersumber dari keterbatasan arsitektur pangkalan data, melainkan disebabkan oleh fenomena *CPU bottleneck* dan *thermal throttling* di lapisan aplikasi. Algoritma Bcrypt secara masif memonopoli siklus CPU, sehingga memblokir *event-loop* Node.js yang bersifat *single-threaded* dan mencegah penyelesaian koneksi I/O ke basis data. Temuan penelitian ini menyarankan bahwa untuk aplikasi dengan beban autentikasi tinggi, perdebatan jenis basis data menjadi kurang relevan tanpa adanya pemisahan (*decoupling*) fungsi kriptografi dari logika utama peladen (*microservices architecture*).

**Kata Kunci**—PostgreSQL, MongoDB, Node.js, High-Concurrency, Bcrypt, Bottleneck, Throughput.

***Abstract***—*This study tests and compares the performance of PostgreSQL (SQL) and MongoDB (NoSQL) in a Node.js-based authentication system under high-concurrency conditions. Testing was conducted using the Autocannon tool with 500 concurrent connections for 30 seconds, utilizing the Bcrypt hashing algorithm (10 salt rounds). Experimental results show that PostgreSQL significantly outperformed MongoDB, maintaining an average throughput of 14.67 Requests per Second (RPS), whereas MongoDB only achieved 0.31 RPS with a high failure rate (1,992 timeouts). Failure analysis revealed that the performance anomalies and bottlenecks did not originate from database architecture limitations, but rather from CPU bottlenecks and thermal throttling at the application layer. The Bcrypt algorithm heavily monopolized CPU cycles, thereby blocking the single-threaded Node.js event-loop and preventing the completion of database I/O connections. The findings suggest that for applications with heavy authentication loads, debating the type of database becomes less relevant unless cryptographic functions are decoupled from the main server logic (microservices architecture).*

***Keywords***—*PostgreSQL, MongoDB, Node.js, High-Concurrency, Bcrypt, Bottleneck, Throughput.*
